# fnmap --hooks: Claude Code Hooks 自动配置

## 概述

为 fnmap 新增 `--hooks` 命令，自动检测项目工具链并生成 Claude Code hooks 配置，实现：
- .fnmap 文件写保护（禁止 AI 修改）
- 代码变更后自动更新 fnmap 索引
- 自动运行代码质量检查（tsc/eslint/biome/prettier/test），错误反馈给模型自动修复

## 触发方式

- **独立命令** `fnmap --hooks` — 可重复执行，幂等更新
- **集成到 `--init`** — 作为初始化流程的新步骤

## 自动检测逻辑

读取 `package.json` 的 dependencies/devDependencies 和配置文件，检测以下工具：

| 工具 | 检测方式 |
|------|----------|
| TypeScript | `typescript` in deps 或 `tsconfig.json` 存在 |
| ESLint | `eslint` in deps 或 `.eslintrc*`/`eslint.config.*` 存在 |
| Biome | `@biomejs/biome` in deps 或 `biome.json`/`biome.jsonc` 存在 |
| Prettier | `prettier` in deps 或 `.prettierrc*`/`prettier.config.*` 存在 |
| Vitest | `vitest` in deps |
| Jest | `jest` in deps 或 `jest.config.*` 存在 |
| Mocha | `mocha` in deps |

## 生成的 Hooks

### 1. PreToolUse: .fnmap 文件保护（始终启用）

- **事件**: PreToolUse，matcher: `Edit|Write`
- **行为**: 检测 file_path 是否以 `.fnmap` 结尾，是则 deny
- **实现**: 内联 node 命令，读取 stdin JSON 检查路径

### 2. Stop: 自动质量检查

一个 Stop hook 执行质量检查脚本，按以下顺序：

1. **前置检查**: `git diff --name-only` 检测是否有 JS/TS/Vue 文件变更，无变更则跳过
2. **fnmap 更新**: `fnmap --changed`（始终执行，静默）
3. **TypeScript**: `tsc --noEmit` → 有错误则 **block**
4. **ESLint/Biome**: lint 变更文件 → 有错误则 **warn**（systemMessage）
5. **Prettier**: `prettier --check` 变更文件 → 有问题则 **warn**
6. **测试**: `vitest run`/`jest`/`mocha` → 失败则 **block**

### 错误反馈分级

| 级别 | 工具 | Hook 输出 | 效果 |
|------|------|-----------|------|
| **block** | tsc, test | `{"decision":"block","reason":"..."}` | 阻止停止，模型必须修复 |
| **warn** | eslint, biome, prettier | `{"systemMessage":"..."}` | 提示但不阻止 |

## 输出文件

### .claude/settings.json

合并写入，不覆盖已有配置。结构：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "<inline node script>",
          "statusMessage": "检查 .fnmap 文件保护..."
        }]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/quality-check.sh",
          "timeout": 120,
          "statusMessage": "代码质量检查中..."
        }]
      }
    ]
  }
}
```

### .claude/hooks/quality-check.sh

动态生成的质量检查脚本，只包含检测到的工具对应的检查逻辑。脚本结构：

```bash
#!/bin/bash
# Auto-generated by fnmap --hooks

cd "${CLAUDE_PROJECT_DIR:-.}" || exit 0

# 检测变更文件
CHANGED=<git diff logic>
[ -z "$CHANGED" ] && exit 0

BLOCK_ERRORS=""
WARN_MESSAGES=""

# fnmap 更新（始终包含）
fnmap --changed 2>/dev/null || true

# [按检测结果动态插入各工具的检查段]
# TypeScript (block)
# ESLint/Biome (warn)
# Prettier (warn)
# Test runner (block)

# 输出结果
if [ -n "$BLOCK_ERRORS" ]; then
  echo "{\"decision\":\"block\",\"reason\":$BLOCK_ERRORS}"
elif [ -n "$WARN_MESSAGES" ]; then
  echo "{\"systemMessage\":$WARN_MESSAGES}"
fi
```

## 幂等性

- 重复运行 `fnmap --hooks` 会重新检测并**更新**已有配置
- 通过检查 settings.json 中是否已存在 fnmap 相关 hooks 来决定是更新还是新增
- 使用固定标识（如 `statusMessage` 内容）来定位已有的 fnmap hooks

## 代码改动范围

1. **src/cli/index.ts** — 新增 `--hooks` 选项
2. **src/types/index.ts** — CLIOptions 添加 `hooks?: boolean`
3. **src/main.ts** — 新增 hooks 安装逻辑：
   - `detectTools(projectDir)` — 检测工具链
   - `generateQualityScript(tools)` — 生成质量检查脚本
   - `installHooks(projectDir, tools)` — 写入 settings.json
   - `executeHooksSetup(projectDir)` — 交互流程
4. **src/main.ts** — `executeInitInteractive` 中新增 hooks 步骤

考虑到 main.ts 已经较大（539 行），hooks 相关逻辑抽取为独立模块：
- **src/hooks/index.ts** — hooks 安装的全部逻辑
